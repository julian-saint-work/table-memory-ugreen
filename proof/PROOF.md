# Table Memory — local rehearsal proof

This is a **local rehearsal**, not a UGREEN NAS run. It answers qdee's three checks with an executed artifact rather than another opinion.

## What was run

- Synthetic recipe cards rendered as images: `fixtures/jollof-mama.png`, `fixtures/jollof-aunty.png`.
- A synthetic PDF: `fixtures/coconut-rice.pdf`, which states a four-serving yield.
- A synthetic voice note: `fixtures/voice-note.mp3`, generated with ElevenLabs TTS through the local `sag` client and transcribed with the ElevenLabs Scribe v2 hosted API from a local script, **for rehearsal only**.
- Local OCR with `tesseract` and PDF text with `pdftotext`.
- Controller-side first session, then a separate second-session script and a separate read-back verifier.

No UGOS delegate, permission prompt, installation, NAS save or NAS read-back ran.

## Result

- `run/review.md` — two jollof branches; Mama's red-pepper line is `needs_review`; Aunty is `complete`.
- `run/cookbook.md` — both versions preserved separately; attributed fixture answer; source-linked provenance index; shopping list built before saving; scaling from the stated four-serving yield.
- `run/correction-record.json` — the approved red-pepper clarification bound to the Mama source fingerprint and field.
- `run/approved-output.json` — byte counts and hashes of the first-session saved files.
- `run/session-2.md` — generated by `session2.cjs`, which reads the saved record from disk, recomputes the source hash, confirms the branch and field, reuses the correction and leaves Aunty’s branch untouched.
- `run/session-2-checks.json` and `run/readback.json` — actual second-session results and byte-for-byte local read-back results.
- `run/session-2-changed.md` and `run/changed-source-check.json` — a separate changed-source test: the saved correction is rejected when the source fingerprint no longer matches.
- The correction record uses `corrections` as a list, so it can hold none, one or several corrections; every correction carries an ingredient or step locator.
- `run/provenance.json` — source SHA-256 fingerprints and transcript.
- `run/checks.json` — first-session checks; `run/session-2-checks.json` and `run/readback.json` cover reuse and read-back; all local checks pass; `nas_execution: false`.
- `controller.cjs`, `session2.cjs`, `changed-source-check.cjs`, `verify-readback.cjs` — the local scripts, with captured outputs in `run/`.
- `run/trace.json` — controller hash, input hashes, commands, output hashes and limitations.
- `run/commands.log` — exact local commands used for OCR, PDF, TTS/STT and the controller.
- `Table-Memory-Local-Proof.pdf` — one-page visual proof for a reviewer.
- `proof.html` — source of the one-page proof.

## qdee check 1: meaningful difference from Family Recipe Box

The existing entry is strong at reading handwritten recipes, translations, voice memos and source-linked notes. This rehearsal makes a different problem central:

> The same dish exists in two legitimate family versions, and one version has a red-pepper line that is present but blurred, so its quantity is unreadable. Table Memory keeps both branches, shows the difference, flags the unreadable value, presents one focused fixture question, records the fixture answer as attributed, and reuses that approved correction in a later session only while the source fingerprint and field match — without merging the versions or inventing the quantity.

That is a concrete branch-and-review behavior, not a claim that we invented recipe scanning.

## qdee check 2: convincing working result

The generated cookbook preserves both jollof branches, includes the present-but-blurred red-pepper line as `needs_review`, keeps the voice-note transcript attached to the Mama branch, and records the fixture answer as attributed. The original card line remains `needs_review`; the approved clarification supplies “One cup, blended.” as the working quantity for Mama’s version, without rewriting the source. The correction record binds that answer to the Mama fingerprint and the ingredient locator; the second session reuses it as `approved_correction` and keeps it out of Aunty’s branch. The changed-source run rejects the old correction when the fingerprint changes. The coconut rice recipe scales only because its PDF states a yield. The jollof is not scaled because neither card states one.

Boundary: the scripts, captured outputs and trace are included, but the OCR, PDF reader, ElevenLabs TTS and Scribe v2 hosted transcription are rehearsal tools, not UGOS services. They do not prove that the UGOS Skill executed, nor the UGOS photo, document or knowledge experts or a NAS read-back. They prove the local first session, the local second-session decision and the local read-back check. The respondent and approval are fixtures; no actual human interaction or model question-selection is claimed.

## qdee check 3: judge experience

The one-page `Table-Memory-Local-Proof.pdf` shows, in order:

1. two source cards with SHA-256;
2. the branch table and the one focused question;
3. the second-session reopen and reuse of the approved correction, plus changed-source rejection;
4. the cookbook excerpt with provenance and attributed answer;
5. exact shopping-list scaling;
6. pass/not-proven checks.

A reviewer can understand the problem, the result and the NAS value in one page.

## Reproduce

```sh
cd table-memory-proof
tesseract fixtures/jollof-mama.png run/jollof-mama
tesseract fixtures/jollof-aunty.png run/jollof-aunty
pdftotext -layout fixtures/coconut-rice.pdf run/coconut-rice.txt
node controller.cjs > run/controller-output.json
node session2.cjs > run/session-2-output.json
node changed-source-check.cjs > run/changed-source-check-output.json
node verify-readback.cjs > run/readback-output.json
# voice-note.mp3 was generated with ElevenLabs TTS via sag and transcribed with the hosted Scribe v2 API
# review/cookbook/provenance/checks are generated by the local controller step
```

The proof contains synthetic data only. No family data, credentials, personal information or UGOS access was used.
